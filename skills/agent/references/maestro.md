# Maestro in the existing Main conversation

- Read this function guide only when a request explicitly carries Maestro guidance.
  Use the existing Main conversation; the captured role, route, model, permissions and
  approval policy remain binding. This guide creates no additional role or execution mode.
- Keep the original message/source reference, interpretation, assumptions/open decisions
  and success criteria separate in the bounded brief. Reuse actual decisions, pending
  inputs and running work.
- For authorized delegation, apply [task allocation](task-allocation.md) and the matching
  [task binding](task-dispatch.md#task-binding) section. Those contracts own ownership,
  profile/model/settings, session reuse and source/revision/time evidence. If the installed
  runtime lacks allocation support, retain that evidence in Scope and report the limitation;
  never invent accepted structured metadata. Follow [orchestration](orchestration.md#chains)
  for confirmed independent work and cross-loop dependency sequencing.
- Tie reports to exact workflow/task/agent/run IDs and receipts. Distinguish planned,
  accepted, running, waiting, blocked, Human decision, completed and unconfirmed states.
  Relay performer questions in Main; cards, indexes, stale results and proposals prove
  neither approval nor completion.
- Read selected originals on demand instead of copying their bodies into prompts.
  For feedback, preserve the problem time and message/task/run IDs with links to existing
  request, state, events, result and receipt records. Never invent progress, usage or
  performance, double-count token subsets, record credentials or transmit logs externally.
